## 확인된 코드 문제

1. 정기 또는 복구 palm scan에서 이전 ROI의 **현재 프레임 추론**을 건너뛰어, 추적으로 관측할 수 있던 손을 detector 결과만으로 대체할 수 있었다. 현재 프레임에서 성공한 추적을 먼저 보존하고 detector 결과를 중복 제거해 합친다. 충분한 현재 양손 추적에 추가 detector 추론을 반복하지 않는다.
2. 한 손을 잃은 다음에는 그 손의 마지막 ROI가 사라져, 기존 복구 정책이 전체 검출만 재시도했다. 기존 1200ms/최대 4회 복구 범위에서 마지막 ROI를 **새 추론 입력**으로만 사용한다. 과거 관절을 현재 관측으로 복사하지 않는다. 프레임당 palm 최대 1회, hand 최대 5회는 유지한다.
3. 같은 좌우 손 라벨의 검출 두 개도 복구 성공으로 셀 수 있었다. 추적/복구 상태는 classifier와 같은 좌우 슬롯·최고 confidence 선택을 사용한다. 원래 raw 검출 기록은 보존한다.
4. 받치는 손이 정지하면 motion-ratio 분류가 OneHand가 될 수 있다. 기존 `KEEP_ONEHAND` 반환은 쓰러지다 추가 참조를 비교하기 전에 종료했고, 추가 참조 경로의 양손 최소 움직임 조건도 정지한 지지 손을 배제했다. 구성한 정지 지지 손 입력과 메모리 테스트 참조로 기존 실패를 재현했다. 이것은 실제 WORD1229 정확도 시험이 아니다.

OneHand 결과를 재검토하는 경우는 실제 paired 20개 이상·paired 비율 0.60 이상이고 WORD1229 참조가 명확히 가장 가까울 때로 제한한다. 기존 거리 0.45와 상대 거리 0.80 기준을 유지한다. 순수 한 손 입력이나 부족한 양손 관측을 쓰러지다로 만들지 않는다. 구조 등 다른 목표의 OneHand override를 추가하지 않았다. 정상 한 손 수어의 실제 오차단/오탐률은 별도 검증이 필요하다.

NMS IoU 0.3과 hand confidence 0.8은 변경하지 않았다. 사용자의 전체 양손 수어가 실패한다고 가정하지 않는다.

- 제공되지 않았던 예전 영상/32·46프레임 좌표를 재생했다고 주장하지 않는다. 이번 실장치 JSONL과 journal은 별도로 보관했다. UI 화면 캡처는 검출 프레임과 완전히 동기화된 원본 영상이 아니다.

## 인식용 밝기 보정

원래 카메라 미리보기는 capture worker에서 그대로 전송한다. 추론 worker에서만 별도의 BGR 영상을 만든다. 기하 변환·좌표 반전·모델 입력 크기는 변경하지 않는다.

`SIGN_LIGHT_PROFILE`이 설정됐을 때 고정 작업 영역의 축소 영상·상하 10%를 제외한 밝기 평균으로 보정량을 추정한다. 사용자가 지정한 조명에서 시작 후 2초 대기·15관측의 중앙값을 저장한다. 이번 기준값은 약 19.9912다. 기준 파일은 `/data/safehub/recognition-light-20261028.profile`이다. 재부팅 후 같은 파일을 읽는다. 실제 전원 재부팅은 아직 시험하지 않았다.

최초 선형 보정은 밝은 장면에서 gain 0.35 제한에 도달했고 실제 인식이 실패했다. 이를 성공으로 집계하지 않았다. 최종 후보는 기준보다 밝을 때만 감마 1~4 범위의 비선형 휘도 보정을 적용한다. 각 픽셀의 BGR에 동일한 휘도별 비율을 적용해 밝은 부분과 색 비율을 보존한다. 시간 상수 250ms로 변화시키며, 더 어두운 입력을 증폭하지 않는다. 진단 JSONL에 reference/measured/gain/gamma/clipped fraction을 남긴다.

영상 보정은 실제 조명을 재현하거나 이미 포화된 손의 세부·그림자·자동 노출에 의한 블러를 복원하지 못한다. 낮/밤 인식률이 같아졌다고 보장하지 않는다. 카메라의 하드웨어 노출/화이트밸런스를 변경하지 않았다.

재보정은 **잘 되는 조명 상태에서만** 아래 요청 파일을 만들어 다음 프레임부터 수행한다. 기존 기준은 덮어쓰기 전에 별도 파일로 보존한다. 자동 재보정은 하지 않는다.

```sh
touch /data/safehub/recognition-light-20261028.profile.recalibrate
```
