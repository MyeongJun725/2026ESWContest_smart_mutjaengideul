# CSI 낙상 경고 연결 · 2026-10-27

## 동작

홈 화면과 CSI 상태는 재실 여부 대신 낙상 감지 상태를 표시한다. `낙상`, `쓰러짐`, `쓰러지다`를 양성으로, 일상 동작을 음성으로 사용한다. 기존 걷기·정지·앉기 모델을 낙상 모델이라고 표시하지 않는다.

PC 수집 화면에서 일상/낙상을 선택한다. 일상에는 걷기·앉기·정지 등 혼동하기 쉬운 동작을 포함하고, 같은 회차에서 두 종류를 모두 수집한다. 학습 요청의 선택 옵션 `fall_only: true`는 선택 기록의 복사본만 두 범주로 묶는다. 원본 기록과 기존 모델은 보존한다. Pi의 학습 금지는 유지하며, PC 학습 모델을 가져와 사용한다.

실측 입력의 서로 다른 두 추론 결과가 0.5초 이상 낙상으로 유지될 때 경고를 한 번 발생시킨다. 입력이 끊기거나 오래된 결과를 반복 조회하면 확인 시간에 포함하지 않는다. 기존 모델의 점수/차이 기준을 사용한다(기본 0.65/0.15). 실행 간격은 0.6초이며 동시 추론은 한 개로 제한한다. 이 간격은 동작 발생부터의 전체 경고 지연이 아니다. 입력 구간 길이와 추론·조회 시간이 추가된다.

경고는 기존 상황 처리와 장치 제어 경로로 이어지며, 전용 음성은 “낙상으로 의심되는 움직임이 감지되었습니다. 주변 사람의 상태를 확인해 주세요.”다. 실제 의식 상태나 신원을 판단하지 않는다. 일상 판단 2초와 최소 10초 재경고 간격을 모두 만족하면 다시 감시한다. 선택한 유효 낙상 모델과 시작 설정을 저장하며, 수신 신호 확보 후 재개하도록 했다. 전원 재부팅 시험은 아직 하지 않았다.

## 내부 연결

`bridge.py`의 HTTP `/state` 응답에 `fall_detection` 상태를 추가했다. UI가 새 이벤트 ID를 중복 제거한 뒤 기존 상황 처리기로 전달한다. MQTT 토픽/JSON 규격은 변경하지 않았다. CSI 서비스가 새 MQTT 발행기를 추가한 것은 아니다.

`fall_detection`에는 `status`, `eligible`, `event`, `hold_seconds`, `rearm_seconds`, `cooldown_seconds`가 있다. 이벤트에는 기존 키인 `message_id`, `device`, `event`, `confidence`, `priority`, `timestamp`를 사용한다. 모의 입력과 수신 단절에서는 실제 경고를 생성하지 않는다.

## 검증

- Python 정책/Controller 테스트 10개 통과: 짧은 튐, 동일 입력 반복, 단절, 모의 입력, 낮은 점수, 재무장, 학습 복사본 불변성.
- Flutter 관련 테스트 53개 통과: 낙상 상태, 학습/수집 UI, 화면 크기, 상황 경고·장치 제어·전용 음성 선택.
- 관련 Dart 파일 정적 분석 통과.
- Pi5에서 격리 Controller 초기화 및 실제 서비스 상태 응답 확인. 기존 기록 47개 보존. 카메라를 추가로 실행하지 않았다.
- Pi5에 UI 1.5.8 설치 후 AppManager Running 확인. 배치와 서버 설정 JSON 3개 및 네이티브 runner 해시 보존.
- 현재 Pi5 저장소에 낙상 학습 기록과 낙상 전용 모델이 없다. 따라서 실제 낙상 정확도·경보 지연·음성/LED/진동까지의 실제 CSI 종단 시험은 미검증이다. 합성 정책 테스트를 실제 낙상 감지 시험으로 해석하면 안 된다.

## 성능 측정 범위

Pi5의 기존 실측 저장 구간 한 개와 기존 모델로 준비 실행 1회 후 30회 반복 처리했다. 중앙값 112.15ms, 95백분위수 197.86ms(선형 보간), 최대 219.97ms. 새 낙상 실험 30회가 아니며 입력 구간 확보·RF·USB·화면·장치·음성 지연은 제외한다.

별도의 Windows 합성 입력 비교에서 4초 구간 전체 전처리 중앙값은 212.93→52.09ms였다. 이것은 보드 교체나 Pi5 성능 개선 수치가 아니다. 원자료: `docs/wifi-csi/integration-validation/numeric-input-benchmark.json`.
