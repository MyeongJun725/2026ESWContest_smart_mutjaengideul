  전체 의존성 및 필수 심볼 누락 0개를 확인했다. 실제 Pi4에서 camera를 열지 않는
  usage 진입 시험 후 서비스를 전환하고 실행 프로세스의 새 ELF 해시를 확인했다.
- Flutter sound/scenario/MQTT/camera 관련 18개 검사 통과. 도움 수어 닫기 추가 후
  help/overlay/actuation 묶음 21개 통과. 두 묶음에는 중복 검사가 있다.
- fastText 문장/HTTP 9개 검사는 가짜 모델을 사용한다. Windows 기본 cp949로
  읽은 한 검사는 인코딩 오류가 났고 UTF-8 모드에서 9개를 다시 통과했다.
- 실제 마이크의 공유 PCM이 YAMNet에 유입되는 것은 확인했다. 사용자가 지정한
  휴대폰 경보음의 성공 검증은 아직 없으며 앞선 재생 시험은 감지 실패였다.
- '쓰러지다' 실제 양손 복구율, 무동작 점등/소등 오인식률, 전체 행동 정확도는
  아직 측정하지 않았다. 새 버전 실행과 정확도 개선을 동일시하지 않는다.
- Uno가 분리된 상태여서 이번 배포로 모터·LED 실동작을 다시 확인하지 않았다.

최종 1.5.3에서는 실제 Pi5 MQTT에 진단용 `{"text":"아프다"}`와

맞힌 시험이 아니며 실제 신고는 전송하지 않았다. Uno는 여전히 분리된 상태였다.
첫 시도에서는 앱이 종료된 상태로 홈 화면 전환 요청이 기록돼 있어 그 캡처를
성공 근거로 사용하지 않았다. 앱을 다시 열고 Running/active를 확인한 뒤
재시험했다. 마지막에는 자막 표시와 YAMNet PCM age 약 0.52초를 확인했다.

## 복원

Pi4는 새 binary를 원래 경로에 덮어쓰지 않았다. 카메라를 중복 실행하지 않고
기존 서비스로 복원한다. 다음은 **Pi4에서만** 실행하는 명령이다.

```sh
systemctl stop safehub-bootstrap.service
cp -p /data/safehub/backups/before-pr11-20261027-194426/run_camera.sh /data/safehub/run_camera.sh
systemctl start safehub-bootstrap.service
```

복원 후 실행 프로세스 `/proc/PID/exe` 해시가 원래 `5b2f...55499`인지 확인한다.
참조/모델을 변경하지 않았으므로 정상 복원에 다시 덮어쓸 필요가 없다.

Pi5는 앱만 중지한 뒤 보존한 이전 package/bundle과 profile로 복원한다.
개인 설정을 삭제하는 uninstall은 사용하지 않는다. 백업 archive의 `app/`와
`profile/`를 각각 원래 앱/사용자 경로에 복원하고 소유권을 유지한 다음
AppManager로 시작한다. 현재 package, 백업, `deployment.json`을 먼저 대조한다.
