## 코드에서 확인한 범위

- PR #11에는 #9의 양손 추적 복구 및 불완전 접촉 수어 분류 보류 경로가 포함돼 있다.
  실제 장치에서의 개선 여부는 미확인이다.
- `LiveSignSession`은 손 검출이 없는 Idle 프레임에서 새 녹화를 시작하지 않는다.
  따라서 무동작 보고만으로 손 검출 오류·정지 손 분류·후단 메시지 반복 중 어느 것이
  원인인지 확정할 수 없다. 런타임의 실제 실행 경로 역시 확인해야 한다.
- `onehand_classifier.cpp`의 후보에는 점등이 있다. 이 사실만으로 오인식 원인을
  확정하거나 해당 클래스를 삭제하지 않는다. 임계값 임의 조정도 하지 않았다.

## 다음 장치 재현 시 수집할 항목

1. 실행 앱/추론 프로세스의 버전·명령행·사용 모델과 원본 SHA를 기록한다.
2. 손이 전혀 보이지 않는 배경, 손을 내린 자세, 손을 정지해 보인 자세를 각각 구분해
   관찰 시간·점등 출력 횟수·실제 장치 동작 여부를 기록한다.
3. 실패한 양손 단어를 개별 기록하고 성공/실패 횟수, 손이 겹치는 구간, 추론 처리 시간,
   양손 검출 프레임 수와 녹화 종료 사유를 확보한다.
4. 같은 구간의 분류 결과와 기존 MQTT 수신 로그를 대조해 최초 오분류와 중복 전달을 구분한다.
5. 수정 후보 적용 후 무동작 음성 사례와 정상 수어 양성 사례를 함께 재시험한다.

기존 `SW/rpi4_vision_atlas/tools/sign_capture_diagnostics.py`는 지원되는 실행 중
프로세스의 기존 파일 로그를 읽는 수집 도구다. 카메라나 서비스를 재시작하지 않지만
명령행/파일 로그 형태가 일치해야 한다. 현재 작업에서는 장치 접속·로그 수집·서비스 제어·
MQTT 발행·실행본 교체를 수행하지 않았다. 실제 시험은 별도 사용자 지시 후 진행한다.
