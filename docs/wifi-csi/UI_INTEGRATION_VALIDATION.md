## 연결 안정성과 처리 비용 점검 (2026-10-04)

카메라 TCP 연결만으로 정상 영상을 수신 중이라고 표시하던 경우를 재현했다. 이제 정상 크기의 RGBA 프레임이 완성된 뒤 연결 상태를 표시하며, 불완전한 패킷만 들어오면 마지막 영상의 유효 시간이 연장되지 않는다. 잘못된 길이의 프레임은 연결을 정리하고 다시 접속한다. 기존 서버의 320×240 RGBA 및 4바이트 길이 헤더는 유지했다.

카메라의 분할·연속 패킷, 잘못된 길이와 재접속, 불완전한 데이터 지속, 최초 접속 거부 후 복구, 종료 후 콜백·재접속 차단 등 6개 검사가 통과했다. 실제 기기 대신 임의 포트의 loopback TCP 서버를 사용했다.

바이트 수신 버퍼를 고정 크기 배열로 바꾸고 앞부분 삭제·복사를 줄였다. Dart 3.7.2 JIT에서 307,200바이트 프레임을 하나씩 주고받으며 준비 20회 이후 120회를 측정한 결과는 다음과 같다. 각 조건을 번갈아 3회 실행했다.

| 카메라 수신 경로 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 왕복 처리 중앙값 범위 | 22.62–23.14ms | 2.21–2.74ms |
| 측정 프로세스 최대 RSS 범위 | 325.7–326.8MiB | 203.5–204.6MiB |

수치는 Windows의 로컬 수신 경로 비교이며, 카메라 촬영·화면 렌더링·Pi 실물 성능을 포함하지 않는다. [원자료](integration-validation/camera-transport-benchmark.json), [재현 스크립트](../../SW/safehub_app/tool/benchmark_camera.dart)를 참고한다.

CSI 상태 조회는 최신 4.025초만 복사하고 같은 입력·전처리 설정의 중복 요청은 계산 결과를 공유한다. 저장 기록과 모델 목록은 파일 변경 시 다시 읽는다. 원본 런타임 29개와 upstream 6개 파일의 해시는 유지했으며, 표시 파형은 수정 전 결과와 배열 전체가 같음을 확인했다.

| CSI 상태 조회 조건 · 합성 입력 20회 중앙값 | 수정 전 | 수정 후 |
| --- | --- | --- |
| 입력이 그대로인 상태에서 재조회 | 181.82ms | 3.86ms |
| 새 프레임 30개 생성 후 조회 | 189.50ms | 157.12ms |

첫 행은 캐시가 적용되는 경우다. 이 비율을 실제 스트리밍 전체의 성능 향상으로 해석하지 않는다. [수정 전](integration-validation/status-baseline.json), [수정 후](integration-validation/status-optimized.json) 측정은 노트북·합성 데이터·8,400프레임 버퍼·모델 메타데이터 40개 조건이다. 원본 I/Q의 문자열 변환·재파싱 비용은 아직 남아 있다.

손상된 기록·모델 메타데이터는 원본 파일을 보존하고 목록에서 제외하며 경고를 표시한다. 학습 중 모델 교체와 인식 시작을 거부하고, 학습 완료 후 이전 인식 결과를 지운다. 시리얼 timeout으로 나뉜 줄은 이어 받고 과대 입력은 제한하며 재연결 때 상태를 초기화한다. 이 경로를 포함한 Python 검사 29개가 통과했다.

호스트 복사본의 전체 Flutter 검사 135개와 별도 체험 모드 홈 검사 3개가 통과했다. 1024×600, 800×480, 600×800에서 홈·의사소통 화면의 넘침을 수정하고 실제 폰트로 렌더링을 확인했다. 마이크 연타, 지연된 권한 응답, 녹음 취소·종료의 경합을 검사했다. 녹음 임시 파일은 해당 서비스가 생성한 파일만 정리한다.

CSI 화면은 USB 목록을 주기적으로 갱신하고, 늦게 도착한 조회가 새 연결 상태를 덮어쓰지 않게 한다. 명령이 지연돼도 파형 조회는 이어가며, 결과를 모르는 timeout 뒤 변경 명령을 자동 재전송하지 않는다. 잘못된 JSON·중복 ID·유효하지 않은 수치는 오류 안내로 처리한다.

MQTT 검사는 실제 클라이언트와 임의 포트의 TCP 브로커 시험 코드로도 수행했다. 기존 4개 구독 토픽과 QoS, 수어·낙상·가전 명령 수신, shortcut UTF-8 메시지 발행, 최초 접속 거부 뒤 재접속, 연결 도중 종료 등 3개 검사가 통과했다. 팀의 실제 브로커·액추에이터와 통합한 결과는 아니다.

합성 입력 장시간 검사는 별도 임시 저장소와 임의 loopback 포트에서 수행한다. 실행 중인 사용자 앱·측정 기록을 사용하지 않는다. 60분 실행 결과는 완료 후 별도로 기록한다.
