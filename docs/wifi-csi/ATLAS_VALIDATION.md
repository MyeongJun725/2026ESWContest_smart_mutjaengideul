# ATLAS 장치 검증

검증일: 2026-10-04. 대상은 RPi5·RPi4의 ATLAS 26.06.0-246, 기존 CSV 펌웨어를
사용하는 ESP32-C6 송수신기다. Windows 배포 ZIP은 별도의 고정된 릴리스이며,
이 문서의 Pi 설치 변경은 해당 ZIP에 포함되지 않는다.

## 확인한 내용

| 항목 | 결과 |
| --- | --- |
| RPi5 ARM64 Python 3.12.15 | 고정된 CSI 의존성 설치, `pip check` 통과 |
| CSI 테스트 | Windows 50개, RPi5 50개 통과. 테스트 입력은 합성/메모리 포트 |
| 실제 CSI | C6 CSV 입력, 처리 파형 생성, 관찰 수신률 약 58.8Hz |
| 출력 전용 수신기 | DTR/RTS 비활성화, 상태 명령 없이 연결 |
| RPi5 재부팅 | bootstrap·MQTT·CSI·UI 자동 시작, 추가 연결 명령 없이 실제 CSI 수신 |
| UI 실행 상태 | AppManager에서 Running, window active 확인 |
| RPi4 재부팅 | 기존 카메라·수어 서비스 자동 시작, Pi5 카메라 TCP 재연결 |
| MQTT 경로 | 카메라의 과거 주소를 Pi5로 변경, 실제 수어 클라이언트 접속 확인 |
| MQTT 접근 제한 | Pi4의 CONNECT에 CONNACK 0, 미허용 노트북의 연결은 시간 초과 |
| 수집·학습 역할 | Pi에서 합성 입력과 학습 비활성화, 기존 MQTT Topic/JSON 유지 |

초기 ATLAS 설정에서는 `/data`의 unit 파일만 배치했을 때 부팅 시 서비스를
찾지 못했다. 루트의 bootstrap unit이 저장소 마운트 후 서비스를 불러오는
구성으로 수정하고 재부팅을 다시 검증했다. 루트 파일시스템은 설치 후 읽기
전용 상태로 복구했다. 설정 파일과 이전 서비스는 장치에 백업했다.

## 검증하지 않은 내용

- 사람이 수어를 수행하고 화면 자막과 비교하는 최종 사용자 시험
- 행동별 정확도, 낙상 오탐·미탐, 독립된 사람·장소·회차 평가
- 전원 완전 차단 후 복구, 물리 USB 재삽입과 tty 번호 변경
- 장시간 연속 운전, 전 구간 무선 패킷 유실률, CPU·온도 한계
- 외부 터치스크린의 모든 조작과 스피커·마이크 동시 운용

USB 지연 연결·재연결 로직은 메모리 포트 테스트로 검사했다. 이를 물리 USB
분리 시험으로 간주하지 않는다. 원래 수신기 로그 90줄이 초기 거부 수에
포함되었고 짧은 관찰 구간에서 이후 증가하지 않았다. 이 값은 RF 유실률이 아니다.

수어 자막 전송과 카메라 영상 경로는 노트북 MQTT 서버를 사용하지 않는다.
음성 합성·음성 입력은 기존 노트북 HTTP 서버를 참조하며 이번 점검에서 그
서버는 응답하지 않았다. 따라서 **앱 전체의 독립 음성 운용 완료로 보지 않는다**.
기존 음성 서버 코드·모델 이식과 실제 스피커·마이크 시험이 남아 있다.

Pi의 모델 폴더는 비어 있다. 실제 행동 분류에는 PC에서 학습한 호환 모델을
가져와야 하며, 신호 수신만으로 행동 인식 준비가 완료되었다고 표시하지 않는다.

설정과 복구 방법은 [ATLAS 부팅 설정](../../SW/atlas_boot/README.md)을 참고한다.
