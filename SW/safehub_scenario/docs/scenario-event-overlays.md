# 이벤트 팝업과 화면 시연

## 화면 배치 편집 (1.2.0)

홈 오른쪽 위의 격자 아이콘 **화면 배치 편집**을 누릅니다. 편집 중에는 각 카드 위 버건디 제목 막대로 이동하고 오른쪽 아래 손잡이로 크기를 조절할 수 있습니다. 영역이 겹치면 상단 영역 선택 목록에서 원하는 카드를 앞으로 가져옵니다.

**기본 배치**, **카메라 세로형**, **취소**, **배치 저장**을 제공합니다. 상황 카드·카메라·음성자막·최근 알림·도움 요청·CSI 활동의 위치와 크기를 편집하며, 글꼴·색·시나리오 동작을 변경하는 도구는 아닙니다. 영상은 전체 프레임을 유지합니다.

배치는 각 기기의 `SafeHubScenarioData/ui-layout.json`에 저장합니다. 저장 전 값은 `.previous`로 보관합니다. 재실·화재·재난 입력은 편집 중에도 기존 경보 화면을 통해 우선 표시합니다. 배치 편집은 신호 수집·학습 설정을 바꾸지 않습니다.

드래그·크기 변경·세로형 프리셋·저장·새 화면에서 복원을 검사했습니다. 관련 Flutter 26개 검사를 통과했습니다. 화면 전체 블러를 추가하지 않았으며 카드·메뉴의 얕은 그림자와 밝은 표면으로 스타일을 다듬었습니다.

## 터치 화면 개편 (2026-10-26)

`feature/scenario-demo-ui`는 PR7의 고정 커밋 `64e60df`를 바탕으로 화면을 개편한 버전입니다. 아래의 이전 팝업 설명 중 작은 신고 확인창·자동 신고 확인창 흐름은 이 버전에서 사용하지 않습니다.

- 홈의 상단 설명을 압축하고 카메라 62%, 자막 38%로 배치합니다. CSI 활동은 카메라 아래에 표시하며 선택하면 기존 수집·학습 화면으로 이동합니다. 영상은 전체 프레임이 보이도록 contain으로 표시합니다.
- 방송·재난 화면은 원문을 크게 표시하고 확인·도움 선택을 제공합니다. 원문에 없는 장소나 대피 방법을 추가하지 않습니다. 상세 전달 상태는 펼쳐 볼 수 있습니다.
- 구조·아프다 인식과 터치 도움 버튼은 같은 화면으로 연결됩니다. 본인·다른 사람을 구분하고 다른 사람을 선택한 경우에만 반응 여부를 묻습니다. 수어만으로 보호자 낙상을 단정하지 않습니다.
- 가족 전달문·119 신고문은 같은 화면에서 확인·복사합니다. 실제 연락·신고 전송 기능은 없습니다. 화재·재난 중 도움 취소는 해당 위험 알림을 확인 처리하지 않습니다.
- 반복 수어의 재진입에는 8초 억제를 적용하고, 다른 수어가 중간에 들어오면 새 도움 입력을 받을 수 있습니다. MQTT 재전송 표지가 있는 동일 패킷을 중복 처리하지 않습니다. 현재 송신 JSON에 인식 이벤트 ID가 없으므로 시간 억제만으로 동일 행동과 새 행동을 완벽히 구분할 수는 없습니다.
- 일반 배경 AI 요약은 시작 시각 기준 최소 15초 간격으로 모읍니다. 수어 도움 화면·알림·터치 응답은 AI를 기다리지 않습니다. Qwen 모델 교체는 수행하지 않았습니다.

Pi4는 기존 영상·수어 처리를 유지합니다. Pi5는 UI·음성자막을 우선하고 LLM 서비스의 CPU 가중치를 낮췄습니다. 실제 장치의 임시 Pi4 CPU 제한은 과열 대응이며 모델·바이너리 변경과 다릅니다.

검증: 관련 Flutter 24개 통과. 800×480, 1280×900 및 글자 배율 1.35에서 주요 확인·닫기 버튼 접근을 검사했습니다. Pi5 ATLAS 앱 ID `com.atlas.app.safehub_scenario_pr7`, 패키지 1.1.0으로 실제 표시와 카메라·자막 서버 연결을 확인했습니다. 전체 기존 테스트, 재부팅, 실제 수어 정확도·물리 경보 동작까지 검증했다는 뜻은 아닙니다. 이전 화면 문구와 중첩 팝업을 기대하는 기존 테스트는 새 흐름에 맞춘 정리가 남아 있습니다.

기존 설치본·설정 백업: `/data/safehub-pr7/releases/demo-ui-20261026/before-ui-and-settings.tar.gz`. 동일 폴더에 이전 패키지 1.0.0과 신규 1.1.0을 보관합니다. 개인 설정과 패키지는 저장소에 포함하지 않습니다.

## 화면 실행

Python 3와 Flutter SDK가 설치된 PC에서 저장소 루트 기준으로 실행합니다.
처음 실행할 때 Flutter 패키지와 웹 빌드 도구를 다운로드할 수 있습니다.

```sh
python SW/safehub_scenario/tool/run_ui_preview.py
```

Flutter가 PATH에 없다면 실행 파일 경로를 지정합니다.

```sh
python SW/safehub_scenario/tool/run_ui_preview.py --flutter-path "C:/flutter/bin/flutter.bat"
```

브라우저가 자동으로 열립니다. 기본 주소는 `http://127.0.0.1:8766/`이며,
이미 사용 중이면 `--port 8877`처럼 다른 포트를 지정합니다. 종료는 Ctrl+C입니다.
소스만 검사하려면 `--check-only`, 브라우저를 자동으로 열지 않으려면 `--no-browser`를 사용합니다.

도우미는 기존 앱의 `lib`와 `assets`를 임시 호스트로 복사합니다.
그 복사본에서만 ATLAS 전용 플러그인 등록과 브라우저의 로컬 설정 파일 접근을 제외합니다.
저장소의 `pubspec.yaml`, 실제 장비 설정과 원본 앱은 바꾸지 않습니다.
SDK, 빌드 파일, 이미지 복사본을 저장소에 추가할 필요가 없습니다.

## 세 가지 시나리오

체험 모드의 화면 하단에 빠른 시연 버튼이 표시됩니다.

| 버튼 | 팝업 |
| --- | --- |
| ① 방송 화재 | 방송 원문, 대피 안내, LED·베드셰이커 전달 상태 |
| ② 재난 알림 | 재난 종류, 지역·발행 시각과 원문, 원문의 안전 행동 안내 |
| ③ 보호자 도움 | 기존 카메라 영상과 터치 버튼 동시 표시, 반응 여부, 119 요청 문안 |

보호자 도움 창에는 수어 시작 버튼이 없습니다. 기존 수어 인식 결과가
`SituationService.receiveSign`으로 들어오면 도움·구조·쓰러짐 계열 라벨에 대해
‘119에 신고할까요?’를 자동으로 표시합니다. 반복 결과는 중복 창을 만들지 않습니다.
확인하면 해당 사건의 주소·원문·선택한 반응 여부·수어 응답으로 문안을 준비합니다.

연결된 카메라는 기존 영상 스트림을 그대로 사용합니다. 장비 없는 브라우저 시연은
연결 대기를 표시합니다. 수어 결과 수신 후의 UI만 시험하려면 다음 주소를 사용합니다.

- `http://127.0.0.1:8766/?signDemo=help`
- `http://127.0.0.1:8766/?signDemo=collapse`

이 주소는 3초 뒤 **시연 입력**을 주입합니다. 실제 카메라 인식 결과가 아닙니다.
일반 주소에는 자동 수어 입력이 없습니다. 기존 분류기의 ‘구조’는 연결할 수 있지만,
‘쓰러짐’ 인식에는 별도 모델 학습·배포가 필요합니다.

모든 새 팝업과 신고 확인·신고 내용 창은 우측 상단 X로 닫을 수 있습니다.
기존 ‘SafeHub로 돌아가기’도 유지합니다. ‘신고하기’는 현재 **시연 요청 안내**를
표시하며 실제 119 문자·영상통화·접수·출동 처리를 수행하지 않습니다.

## 실기와 검사

ATLAS에서는 기존 앱 설치·연결 절차를 사용합니다. 하단 시연 버튼과 URL 수어 주입은
`APP_LOCAL_PREVIEW=true`일 때만 활성화됩니다. 실제 모드의 사건 수신과
`_sendScenarioSignal`은 기존 MQTT 경로를 유지하며, 명령 제출과 장치 동작 확인을 구분합니다.

LLM 청취·추론, 실제 재난 API 수신, Pi 카메라·CSI·LED·베드셰이커 성능은
이 화면 시연의 검증 범위가 아닙니다. UI 팝업은 활성 사건을 직접 확인하므로
홈 외 다른 탭에서도 표시됩니다. 화면 확인·X 닫기는 위험 해제를 뜻하지 않습니다.

표준 Flutter 호스트 또는 기존 ATLAS 개발 환경에서:

```sh
flutter test test/scenario_event_overlay_test.dart
```

방송·재난·터치·수어 입력, 카메라 동시 표시, 중복 방지, 사건 종료, X 닫기와
신고 버튼 등 신규 동작 검사 10개를 포함합니다. 기존 전체 테스트의 문제를
모두 수정한 변경은 아닙니다.
